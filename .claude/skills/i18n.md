---
name: i18n
description: Internationalisation standards for React frontend (react-i18next) and Express backend (i18next) — all user-visible strings must come from locale JSON files, never hardcoded
---

**Trigger:** Any time frontend or backend code contains user-visible strings — labels, error messages, placeholders, alerts, navigation items, button text, or any text shown to the user.

> **Also apply:** `frontend` and `frontend-testing` when writing frontend i18n code. `backend` and `backend-testing` when writing backend i18n code.

For full design rationale see `docs/design/i18n.md`.

---

## The one rule

**Every string visible to the user comes from a locale JSON file.** No exceptions. Not even "Loading…".

---

## Frontend

### Setup

```bash
npm install i18next react-i18next i18next-browser-languagedetector
```

The singleton lives at `apps/web/src/i18n.ts`. Import it once in `main.tsx` before rendering — never import it inside components.

### Namespace per feature area

| Namespace      | JSON file             | Content                                 |
|----------------|-----------------------|-----------------------------------------|
| `common`       | `locales/en/common.json` | Nav labels, shared buttons, status  |
| `auth`         | `locales/en/auth.json`   | Login, register, session errors     |
| `overview`     | `locales/en/overview.json` | Dashboard strings                 |
| `cards`        | `locales/en/cards.json`  | Credit cards feature                |
| `accounts`     | `locales/en/accounts.json` | Bank accounts feature             |
| `loans`        | `locales/en/loans.json`  | Loans feature                       |
| `investments`  | `locales/en/investments.json` | Investments feature            |
| `insurance`    | `locales/en/insurance.json` | Insurance feature                |

Mirror the same structure under `locales/hi/`.

### Key naming

- `camelCase` keys only.
- Nested objects for logical groups — access with dot notation: `t('errors.loadFailed')`.
- Error sub-keys mirror backend `error.code` values in lowercase: `pan_invalid`, `rate_limit_exceeded`.

```json
// en/cards.json
{
  "pageTitle": "Credit Cards",
  "creditLimit": "Credit Limit",
  "emptyState": "No credit cards linked to this PAN yet.",
  "errors": {
    "loadFailed": "Failed to load credit cards. Please try again."
  }
}
```

### Component usage

```tsx
import { useTranslation } from 'react-i18next';

const CreditCardList: React.FC = () => {
  const { t } = useTranslation('cards');
  return <Typography variant="h5">{t('pageTitle')}</Typography>;
};
```

Specify the namespace in `useTranslation`. Never use the default namespace for feature strings — it pollutes `common`.

For strings with embedded JSX, use `Trans`:

```tsx
import { Trans } from 'react-i18next';
// en/auth.json: { "termsNote": "By continuing you agree to our <1>Terms</1>." }
<Trans i18nKey="auth:termsNote" components={[<span />, <Link href="/terms" />]} />
```

### Language switcher

```tsx
import { useTranslation } from 'react-i18next';
import { Select, MenuItem } from '@mui/material';

const LOCALES = [
  { code: 'en', label: 'English' },
  { code: 'hi', label: 'हिंदी' },
] as const;

const LanguageSwitcher: React.FC = () => {
  const { i18n } = useTranslation();
  return (
    <Select value={i18n.language} onChange={(e) => i18n.changeLanguage(e.target.value)} size="small">
      {LOCALES.map(({ code, label }) => (
        <MenuItem key={code} value={code}>{label}</MenuItem>
      ))}
    </Select>
  );
};
```

### Number and date formatting

**Do not put formatted numbers or dates in JSON files.** Use the `Intl` API directly:

```tsx
// Currency — always INR, always en-IN grouping regardless of UI language
const formatINR = (amount: number): string =>
  new Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' }).format(amount);

// Date — adapt locale identifier from i18n.language
const formatDate = (date: Date, lang: string): string =>
  new Intl.DateTimeFormat(lang === 'hi' ? 'hi-IN' : 'en-IN', {
    day: '2-digit', month: 'short', year: 'numeric',
  }).format(date);
```

### Testing frontend i18n

Wrap with the real i18n instance — never mock `useTranslation`:

```tsx
import { I18nextProvider } from 'react-i18next';
import i18n from '../../i18n';

const renderWithI18n = (ui: React.ReactElement) =>
  render(<I18nextProvider i18n={i18n}>{ui}</I18nextProvider>);
```

Assert on the translated string, not the key:

```ts
expect(screen.getByText('Credit Cards')).toBeInTheDocument(); // correct
expect(screen.getByText('cards.pageTitle')).toBeInTheDocument(); // wrong
```

Add `renderWithI18n` to the standard `renderWithProviders` helper used across all component tests.

## Backend

### Setup

```bash
npm install i18next i18next-fs-backend
```

### Locale files

```
apps/api/src/locales/
├── en.json
└── hi.json
```

Each file has two top-level groups: `error` and `validation`.

```json
// en.json
{
  "error": {
    "pan_invalid": "PAN format is invalid",
    "pan_already_registered": "A PAN profile already exists for this account",
    "pan_not_found": "No PAN profile found for this account",
    "unauthorized": "Authentication required",
    "forbidden": "You do not have permission to perform this action",
    "not_found": "The requested resource was not found",
    "rate_limit_exceeded": "Too many requests. Please try again in a few minutes.",
    "internal": "An unexpected error occurred. Please try again."
  },
  "validation": {
    "pan_required": "PAN is required",
    "pan_format": "PAN must be 10 characters: 5 letters, 4 digits, 1 letter (e.g. ABCDE1234F)",
    "email_required": "Email address is required",
    "email_invalid": "Enter a valid email address",
    "password_min": "Password must be at least 8 characters",
    "password_required": "Password is required"
  }
}
```

### Singleton (`apps/api/src/i18n.ts`)

```ts
import path from 'path';
import i18next from 'i18next';
import Backend from 'i18next-fs-backend';

export const initI18n = async (): Promise<void> => {
  await i18next.use(Backend).init({
    fallbackLng: 'en',
    supportedLngs: ['en', 'hi'],
    backend: { loadPath: path.join(__dirname, 'locales/{{lng}}.json') },
    interpolation: { escapeValue: false },
  });
};
```

Call `await initI18n()` in `app.ts` before `app.listen()`.

### Locale middleware

```ts
import type { Request, Response, NextFunction } from 'express';
import i18next from 'i18next';

declare module 'express-serve-static-core' {
  interface Request { language: string; }
}

export const localeMiddleware = (req: Request, _res: Response, next: NextFunction): void => {
  const raw = req.headers['accept-language'] ?? 'en';
  const requested = raw.split(',')[0]?.split('-')[0]?.toLowerCase() ?? 'en';
  const supported = i18next.options.supportedLngs as string[];
  req.language = supported.includes(requested) ? requested : 'en';
  next();
};
```

Position: after `express.json()`, before `rateLimiter`.

### Error responses

```ts
import i18next from 'i18next';

// In route handler or error middleware:
const message = i18next.t('error.pan_invalid', { lng: req.language });
res.status(400).json({ error: { code: 'PAN_INVALID', message } });
```

The `code` field is always a stable English constant (for frontend branching logic). The `message` is translated.

### Zod messages

```ts
const panSchema = (lng: string) =>
  z.string({
    required_error: i18next.t('validation.pan_required', { lng }),
  }).regex(/^[A-Z]{5}[0-9]{4}[A-Z]$/, i18next.t('validation.pan_format', { lng }));
```

Build the schema inside the route handler after `req.language` is available.

### Testing backend i18n

Always pass `lng: 'en'` explicitly in unit tests:

```ts
const message = i18next.t('error.pan_invalid', { lng: 'en' });
expect(message).toBe('PAN format is invalid');
```

## What is forbidden

| Pattern | Reason |
|---------|--------|
| Hardcoded label strings in JSX | Breaks i18n — use `t('key')` |
| Hardcoded `error.message` in Express routes | Breaks i18n — use `i18next.t(...)` |
| Formatted numbers (₹5,00,000) in JSON files | Use `Intl.NumberFormat` at render time |
| Mocking `useTranslation` in tests | Hides missing translation keys — use real instance |
| `t('key') || 'fallback string'` | i18next handles fallback via `fallbackLng: 'en'` |
